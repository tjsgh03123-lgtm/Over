# OVERDRIVE — 운동 기록

Android용 오프라인 운동 기록·성장 분석 앱 (React Native + Expo + TypeScript + SQLite).
모든 데이터는 기기 내부 SQLite에 저장되며 서버·AI API 호출이 전혀 없습니다.

## 검증 상태 (중요)

| 구분 | 상태 |
|---|---|
| 성장 통계, 기간, 1RM, AI 루틴 파서, 신체 항목(직접 추가), 1RM 분리·횟수별 보기, 루틴(사이클) 모델·AI 프롬프트 형식, 시간 표시, 세트 입력 시작값 | **테스트 완료** (`tests/run.ts`, 66개 통과 — 실시간 횟수 세기 계산 포함) |
| SQLite 스키마(12개 테이블), 기본 루틴 시드, 저장소, 세션 자동 저장/복원, 기록 수정·삭제 반영, 루틴 만들기·날 편집·사용 중 루틴 선택, 예전 기본 루틴 정리(마이그레이션), 신체 항목 추가·숨김·삭제, 날 끌어서 옮기기, 세트 휴식 설정, 1RM 세트, 보는 운동 선택, 첫 실행 설정 표시 조건, 앱 시작 시 지난 루틴 확인, 운동 타이머 기록, JSON 백업·복원(롤백 포함), CSV | **실제 SQLite 엔진에서 테스트 완료** (`tests/db.ts`, 42개 통과) |
| 도메인·DB 코드 TypeScript strict 타입 검사 | 통과 |
| 화면(UI) 코드, 차트, 파일 공유/선택, 클립보드 | **작성만 됨, 실행·타입검사 미수행** — 제작 환경에서 npm 레지스트리 접근이 막혀 의존성을 설치하지 못했습니다. 처음 실행할 때 사소한 타입/버전 오류가 나올 수 있습니다. |
| 실시간 횟수 세기 카메라 모듈(Kotlin + CameraX + MediaPipe) | **작성만 됨 — 이 환경에서는 빌드·실행 불가**(구글 서버 접근 차단). GitHub Actions에서 빌드되며 실제 기기 확인이 필요합니다. |
| Android 빌드(APK) | GitHub Actions(`build-apk.yml`)에서 수행 |

`package.json`의 Expo 관련 버전(SDK 54 기준)은 설치 전에 확인되지 않았습니다. 설치 후 `npx expo install --fix`로 맞추세요.

## 실행 방법

```bash
npm install
npx expo install --fix      # 의존성 버전을 Expo SDK에 맞춤
npm test                    # 로직·DB 테스트 (Node 22 이상)
npx tsc --noEmit            # 전체 타입 검사 (UI 포함, 처음 실행 시 오류가 나오면 알려주세요)
npx expo start --android    # 개발 서버
```

```bash

# APK 위치: android/app/build/outputs/apk/release/app-release.apk
```

**방법 3 — GitHub Actions**: `.github/workflows/build-apk.yml` 참고 (수동 실행 → Artifacts에서 APK 다운로드, 미검증).

```
  routine.ts                 루틴 모델: 날, 칸 배치(N일 반복/요일 고정), 오늘의 날 계산
  cycle.ts                   사이클 날짜 계산
  format.ts                  경과·총 시간 표시, 세트 입력 시작값(앞 세트 이어받기)
  stats.ts                   날짜별 최고/평균/볼륨, 변화량(kg·%), 기간, 추정 1RM
  intensity.ts               (숨김) 예전 강도 태그 상속 — 화면에서는 쓰지 않음
  parser.ts                  AI 루틴 파서 (JSON / Markdown 표 / 목록 / 일반 텍스트)
  importSchema.ts            외부 AI용 JSON Schema + 복사용 프롬프트
src/db/
  schema.ts                  DDL (12개 테이블) / seed.ts 기본 루틴 / repo.ts 저장소

src/screens/                 화면
tests/                       run.ts(로직), db.ts(실제 SQLite 통합 테스트)
```

## 디자인 원칙: 심플이 최고

- 화면은 **흑·백·회색만** 사용하고, **색은 그래프에만** 씁니다. 그래프 선 색은 설정 → 화면에서 8가지 원색 중 고를 수 있습니다(중량/몸무게/골격근량/체지방량/체지방률).
- **라이트/다크** 모드를 설정에서 선택합니다(기본 다크). 선택은 기기에 저장됩니다.
- 운동 입력은 `kg × 회 + ✓`만 보입니다. 메모·준비 세트·종목 삭제는 종목의 **옵션**을 눌러야 나옵니다.
- **성장 분석(운동 중량)**: 먼저 ‘운동 고르기’에서 **내 루틴에 있는 운동 중 보고 싶은 것만** 체크합니다(여러 날·여러 루틴에 같은 운동이 있어도 한 번만 표시, 루틴에 없는 운동은 ‘다른 운동 추가’). 첫 화면은 고른 운동의 한 줄 목록(현재 최고·직전 대비·작은 추이선)이고, 운동을 누르면 **평소 운동**(횟수 칩 5회·8회·10회… 또는 전체 + 기간)과 **1RM** 두 탭이 나옵니다. 1RM은 운동 기록에서 세트 번호를 눌러 본 → 준비 → 1RM 순으로 바꿔 표시한 세트만 모으며, 평소 운동 그래프·볼륨·지난 기록 힌트에는 섞이지 않습니다.
- **신체 변화**: 기본 항목(몸무게·골격근량·체지방량·체지방률)과 이름·단위를 정해 직접 추가한 항목(숫자만, 예: 허리둘레 cm)을 같은 방식으로 기록·그래프로 봅니다. 항목마다 그래프 색 선택, 쓰지 않는 기본 항목은 숨기기(기록은 남음), 직접 만든 항목은 삭제(값도 함께 삭제). 인바디 사진 인식은 없고 **직접 입력만** 합니다.
- **끌어서 순서 바꾸기**: 루틴의 날 목록과 날 안의 운동 목록은 줄 오른쪽 끝 ≡를 길게 누른 채 끌면 순서가 바뀝니다(떠오르는 진동, 화면 가장자리에서 자동 스크롤). 순서 계산은 `domain/reorder.ts`(테스트됨), 끌기 제스처는 `ui/ReorderList.tsx`(터치 동작은 폰에서 확인 필요).
- **세트 종류**: 운동 기록에서 세트 번호를 누르면 줄 아래에 본 세트 / 준비 세트 / 1RM 측정 선택과 삭제가 바로 나옵니다.
- **세트 사이 휴식 타이머**: 세트를 ✓하면 카운트다운(+30초·건너뛰기), 끝나면 진동합니다. 길이는 루틴 날 편집의 종목별 ‘휴식(초)’ → 없으면 설정의 기본(끄기/60/90/120/180초, 기본 90초). 준비 세트와 마지막 세트에서는 시작하지 않습니다.
- **첫 실행 설정**: 새로 설치했을 때만 한 번 — 시작 화면 예시에서 라이트/다크 선택 → 1) 그래프(색·직접 항목) 2) 신체 정보 3) 루틴 시작 방법(직접 만들기 / AI로 가져오기 / 나중에). 모두 건너뛸 수 있고, 설정 → 관리 → ‘처음 설정 다시 하기’로 다시 열 수 있습니다.

## 사용 흐름

- **홈**: 사용 중인 루틴의 오늘 해당하는 날에서 ‘운동 시작’ / ‘자유 운동’. 오늘 정해진 루틴이 없으면 ‘루틴 만들기’ / ‘자유 운동’.
- **타이머**: ‘운동 시작’을 누른 시각부터 흐르고(앱을 껐다 켜도 이어짐), 모든 세트를 마치면 ‘타이머 종료’ 버튼이 나옵니다. 시작·종료 시각과 총 시간이 저장되어 캘린더·운동 기록에 표시됩니다.
- **루틴 = 사이클 한 개 전체**: 루틴 탭에서 루틴을 만들고(여러 개 가능, 하나를 ‘사용 중’으로 선택), 루틴 안에 ‘날’(1일차, 2일차 …)을 추가해 날마다 이름·종류(웨이트/유산소/휴식)·종목을 정합니다. 요일·시작일은 루틴의 **세부 설정**입니다: ‘N일 반복’(순서대로 N일마다 반복, ‘오늘은 N일차’로 위치 맞춤) 또는 ‘요일 지정’(날마다 요일 지정, 나머지 요일은 휴식).
- **기본 루틴 없음**: 앱은 기본 루틴을 만들지 않습니다. 예전 버전의 기본 루틴·요일 일정·미사용 기본 종목은 업데이트 후 처음 실행할 때 한 번 삭제되고, 완료한 기록과 그래프는 유지됩니다.
- **AI 루틴 가져오기**: 프롬프트를 복사하거나 `.txt` 파일로 저장해 다른 AI에 넣습니다(사용자가 원하는 루틴을 적는 자리는 맨 아래 구분선 밑). AI가 만든 결과는 붙여넣기 또는 `.txt` 파일 불러오기로 가져와 미리보기에서 고친 뒤 저장합니다.
- **앱 시작 팝업**: 지난 7일 안에 예정이었는데 완료한 운동이 없는 날이 있으면 ‘루틴대로 하기 / 오늘만 자유 운동 / 넘어가기’를 묻습니다(하루 한 번). ‘N일 반복’ 루틴에서 ‘루틴대로 하기’를 고르면 이후 일정이 이어서 밀립니다.
- **세트 입력**: 첫 세트는 지난 기록 중량·횟수에서, 다음 세트는 앞 세트 값에서 시작합니다(칸을 누르면 그 숫자가 들어가 고칠 수 있음). ✓를 누르면 칸의 숫자로 확정. 칸을 누르면 ± 버튼(설정에서 1 / 2.5 / 5kg)이 나타납니다.
- **강도(고중량/중간중량/저중량) 기능은 삭제**했습니다. 예전 기록의 값은 데이터에 남아 있을 수 있지만 화면·그래프에서는 쓰지 않습니다.

- **실시간 횟수 세기**: 운동 화면에서 종목의 ‘📷 실시간 횟수 세기’를 누르면 **바로 카메라가 켜지고**(시작 버튼 없음), 운동 종류를 고르지 않아도 각도(팔꿈치·무릎·고관절·어깨)와 위치(손목 위아래·좌우, 몸·골반 위아래, 어깨 으쓱, 뒤꿈치 들기) 중 크게 반복되는 동작을 찾아 횟수를 자동으로 셉니다. 사이드 레터럴 레이즈처럼 팔꿈치가 펴진 채 움직이거나 골반이 안 보여도 손목 위치로 셉니다. 셀 때마다 진동하고 횟수를 소리로 읽어 줍니다(‘하나, 둘, 셋…’, 끄기 가능). 마지막·평균 렙 시간 표시, ‘이 횟수 사용’을 누르면 그 종목의 첫 미완료 본 세트 횟수에 들어갑니다(✓는 직접). 민감도(쉬움/보통/엄격), 모델(빠름/정밀), 앞/뒷카메라 전환. 카메라 화면이 안 나오면 ‘카메라 다시 켜기’. 인터넷 없이 폰에서만 처리합니다.
  - 구조: `modules/pose-camera`(Kotlin Expo 모듈·뷰) · `src/domain/liveCount.ts`(순수 계산) · `src/ui/LiveCountModal.tsx`. 포즈 모델 2종은 저장소에 넣지 않고 빌드 워크플로가 내려받아 앱에 포함합니다(로컬 빌드 시 `modules/pose-camera/android/src/main/assets/`에 `pose_landmarker_{lite,full}.task` 필요).

## 설계 메모

- **그래프는 항상 저장된 원본 세트 기록에서 계산**합니다. 필터는 기록을 바꾸지 않으며, 기록을 수정·삭제하면 화면이 `version` 값으로 자동 재조회됩니다.
- **완료(done)된 운동만** 통계에 들어갑니다. 진행 중 운동은 자동 저장되어 앱을 종료해도 복원되고, 완료를 누르면 그래프에 반영됩니다. 완료 후 '기록 수정'을 누르면 다시 편집할 수 있습니다.
- 통계 대상: 완료 체크 + 본 세트 + 중량 입력된 세트. 준비 세트는 '준비 세트' 토글로 따로 조회합니다.
- 어시스트 운동은 **중량이 낮을수록 더 좋은 기록**으로 계산합니다(종목 관리에서 방식 변경 가능).
- 종목 이름을 바꿔도 `exercise_id`로 기록이 이어지고, 옛 이름은 별칭으로 남아 자유 운동/AI 가져오기에서도 같은 종목으로 합쳐집니다. 루틴을 지워도 완료 기록은 유지됩니다.
- 기본 루틴 월요일 10번 "행잉 레그 레이즈 대체 운동 미정"은 **'행잉 레그 레이즈 대체 (미정)'** 이라는 별도 종목으로 넣었습니다(행잉 레그 레이즈 기록과 섞이지 않게). 종목 관리에서 이름을 바꾸세요.
- 그래프 예시 숫자(100kg/102.5kg…)는 어디에도 저장하지 않으며, 테스트에서도 가상 데이터를 메모리 DB에서만 사용합니다.

## 데이터 보관

- 앱 내부 저장소(SQLite)라서 브라우저 기록·쿠키·사이트 데이터 삭제와 무관합니다.
- 앱을 삭제하면 데이터도 삭제됩니다. 설정 → JSON 전체 백업으로 주기적으로 내보내세요(공유 시트로 드라이브·카톡 등에 저장).

## 알려진 한계

- AI 루틴 파서는 일반 텍스트에서 오인식할 수 있으므로 미리보기에서 수정 후 저장하는 흐름입니다. 가장 정확한 방법은 앱이 제공하는 프롬프트로 JSON을 받는 것입니다.
- 앱 아이콘/스플래시는 기본값입니다. `assets/`를 추가하고 `app.json`에 지정하세요.

## 실시간 횟수 세기 – 세트 자동 진행 · 운동 종류 · 맨몸 운동
- **세트 자동 진행**: 세트당 목표 횟수·세트 수·쉬는 시간을 정하면, 목표를 채울 때 "N세트 완료"를 말하고 쉬는 시간을 초 단위로 읽어 준 뒤 "N+1세트 시작"과 함께 자동으로 다음 세트를 셉니다. 쉬는 중에는 세지 않고, "쉬기 건너뛰기"로 바로 시작할 수 있습니다. 끝나면 세트별 횟수가 세션 기록에 한 번에 들어갑니다.
- **운동 종류 선택**: 자동 / 팔 굽히기 / 하체 / 사레레·팔 들기 / 맨몸(푸시업·풀업) / 종아리. 고르면 그 동작만 봅니다. 맨몸 종목은 기본으로 '맨몸'이 선택됩니다.
- **맨몸 운동**: 홈의 "맨몸 운동 시작"으로 시작하면 종목이 체중 모드로 만들어지고, 무게칸은 추가 중량(+kg, 선택)입니다.
- **기본 종목(바벨·덤벨 27개)**: 가슴·등·어깨·하체·팔 부위별로 종목 선택창에서 바로 추가. 종목마다 볼 동작(팔 굽힘·스쿼트·힌지·사레레·슈러그·종아리)과 카메라 위치 안내가 정해져 있고, 내 루틴의 종목 이름(별칭 포함)을 인식해 자동 적용합니다.
- 앱 아이콘·스플래시: 스파르탄 투구 (적응형·테마 아이콘 포함).

## 루틴 한 종목씩 진행 · 슈퍼세트
- 루틴으로 시작한 운동은 기본으로 **지금 할 종목만** 보여 줍니다 (위에 "종목 3/6", 다음 종목과 카메라 위치 안내). "전체 목록" 버튼으로 언제든 전체를 볼 수 있어요. 자유 운동은 전체 목록이 기본입니다.
- 세트를 끝내면 **세트 간 휴식**, 종목의 마지막 세트를 끝내면 **종목 간 휴식**(기본 180초)이 나오고, 끝나면 다음 종목이 자동으로 표시됩니다. 종목 간 휴식은 휴식 중 −30/+30초로 바꿀 수 있고 바꾼 값이 다음부터의 기본값이 됩니다. 종목 간 휴식 때 다음 종목 이름을 음성으로 알려 주고 📷로 바로 횟수 세기를 시작할 수 있어요.
- "나중에 하기"는 지금 종목을 뒤로 미룹니다. "이 종목 끝내기"는 남은 세트를 지우거나 건너뜀으로 남길지 물어봅니다. (건너뜀·미룸은 화면을 나가면 초기화)
- **슈퍼세트**: 루틴 날 편집에서 "위 종목과 슈퍼세트로 묶기". 운동 중에는 묶인 종목을 번갈아 하고, 한 바퀴를 다 돌았을 때만 세트 간 휴식이 나옵니다.
- 실시간 횟수 세기에 −1/+1 보정 버튼이 있습니다.

## 운동 화면·프로필 개편 (짐워크 참고, 흑백 유지)
- **운동 화면**: 상단에 볼륨·완료 세트·종목 요약. 종목 카드에 장비·휴식·e1RM·**지난번 대비 볼륨**. "불러오기"로 지난 기록 채우기. 세트 번호를 누르면 **입력 시트**(큰 −/+, 최근·추천, 남은 세트 통일, 세트 종류, 삭제). 바벨은 **바+원판 계산**(바 무게는 설정). 슈퍼세트는 태그와 세로선으로 표시.
- **휴식 저장**: 세트 간 휴식 중 −/+30초로 맞춘 뒤 "저장"으로 *이 종목만* / *모든 종목에* 선택.
- **완료**: 남은 세트가 있으면 확인 후 완료, 완료하면 **요약 카드**(시간·볼륨·세트·종목별 e1RM·주 연속 기록)를 이미지로 저장·공유.
- **루틴 시작 전 미리보기**: 홈의 "운동 시작"을 누르면 종목 수·예상 시간·부위별 세트 수·종목 목록을 보여 줍니다.
- **프로필 탭**(설정은 ⚙): 이름, 이번 달 운동일·목표·주차별 체크, 주 연속 기록, 3대 운동 예상 1RM 합계, 신체 기록, 1RM 계산기, 내 메모.
- **분석 > 부위별**: 주간 부위별 완료 세트·볼륨 막대.
- **종목 데이터**: 바벨·덤벨 27개 + 머신·케이블·맨몸 종목을 부위(가슴·등·어깨·하체·팔·복근)와 장비(바벨·덤벨·머신·케이블·맨몸)로 구분. 장비에 따라 무게 칸 이름이 달라집니다(한 손 무게 / 머신 무게 등).

## 종목 목록 부위별 정리 · 시작 전 설정 · 준비 시간 · 휴식 화면 · 진행 방식
- **종목 선택창**: 목록은 하나이고 부위별(가슴·등·어깨·하체·팔·복근·기타)로 묶입니다. 각 부위 안에서 *직접 추가한 종목이 맨 위*, 그 아래에 기본 종목이 나오고 중복은 합쳐집니다. 새 종목은 선택한 부위 칩 아래에 들어갑니다(아무것도 안 골랐으면 기타).
- **종목 관리**: 부위 칩으로 거르고 부위별로 묶어 보여 줍니다. 종목을 누르면 펼쳐져 이름·**부위 변경**·방식·삭제가 나옵니다. 부위를 바꾸면 분석의 부위별 통계에도 반영됩니다(지정한 부위가 이름 자동 분류보다 우선).
- **시작 전 미리보기**: 제목을 눌러 *다른 루틴으로 바꾸기*, **컨디션**(100/75/50% — 무게 −10%·−20%, 세트 감소, 이번 운동에만 적용), **진행 방식**(직접 기록 / 카메라 / 박자), **순서 변경**(▲▼, 이번 운동에만 적용).
- **준비 시간**: 카메라·박자 세기에서 세트 시작 전에 준비 시간(기본 10초, 0~30초, 설정 저장)이 있고 끝나기 전 3·2·1을 소리로 알려 준 뒤 "시작"합니다. 첫 세트 전과 쉬는 시간이 끝난 뒤에 들어가며 "바로 시작"으로 건너뛸 수 있습니다.
- **박자로 세기**: 카메라 없이 앱이 정해 둔 박자(한 회당 1~10초, 기본 3초)로 횟수를 소리 내어 세고, 세트 흐름(준비→세기→휴식)은 카메라 방식과 같습니다.
- **휴식 화면**: 세트 간·종목 간 휴식이 큰 타이머 화면으로 나오고, ±10초(종목 간은 ±30초)로 조절합니다. 바로 다음 세트(무게·횟수) 또는 다음 종목을 보여 주고, 끝나기 3초 전부터 3·2·1을 말합니다. "작게 보기"로 아래 줄로 줄일 수 있습니다.
- **진행 방식**: 운동 화면 위 "진행" 칩으로 바꿀 수 있고(마지막 선택을 기억), 카메라/박자일 때는 종목 카드와 휴식 화면에 시작 버튼이 나옵니다. 종목 카드 안에는 항상 📷 카메라로 세기 / ⏱ 박자로 세기 버튼이 있습니다.

## 첫 화면(홈) 개편 (짐워크 시작 화면 참고, 흑백 유지)
- **맨 위**: 날짜 아래에 `이번 주 N회 · N주 연속`, 그 아래 이번 주 월~일 날짜 줄(운동한 날은 채워지고 오늘은 테두리).
- **오늘의 운동 카드**: 제목, **부위 칩**(가슴 9세트 · 어깨 6세트…), `N종목 · 마지막 N일 전`. 카드 오른쪽 `Day 3/5 ▾`를 누르면 **오늘만 다른 날 루틴으로 바꾸기**(확인 후 적용, 일정은 그대로, "원래 일정으로 되돌리기" 가능). "저장한 루틴 보기"는 루틴 탭으로 이동.
- **내 루틴**: 루틴 카드 목록(이름, 부위 요약, 종목 수, **마지막으로 한 지 N일 전**). 누르면 시작 전 미리보기. ⋯로 **보관**하면 홈 목록에서 숨고(루틴 탭에는 그대로) 아래 "보관함"에서 꺼낼 수 있습니다. "+ 새 루틴"은 루틴 탭으로 이동.
- **아래 고정 버튼**: [자유 운동] [운동 시작] (진행 중이면 [이어서 기록하기], 오늘 루틴이 없으면 [루틴 고르기]/[루틴 만들기]).
- 홈에서 "AI 루틴 가져오기"·"인바디" 버튼을 뺐습니다. AI 가져오기는 루틴 탭, 신체 기록은 프로필의 신체 카드에서 합니다. "이번 주 운동"과 "최근 중량 성장"은 아래에 그대로 둡니다.

## 루틴 개편: 칸 배치 · 5단계 만들기
- **모델**: 루틴 = 만들어 둔 ‘날’(Day) 목록 + 칸(`slots`) 배치. 칸에는 날 id를 넣고, 비어 있으면 휴식이다. 같은 날을 여러 칸(여러 요일)에 놓을 수 있다.
  - **N일 반복**(cycle): 칸 수 = 반복 일수(1~28). 시작일부터 Day 1 … Day N을 돌고 다시 Day 1로 돌아간다.
  - **요일 고정**(weekday): 항상 7칸(칸 번호 = 요일). 월요일부터 보여 준다.
  - 방식은 루틴을 만들 때 고르고, 나중에 바꿀 수도 있다(Day 1~7 ↔ 월~일로 옮기고, 7칸을 넘는 Day는 칸에서만 빠짐 — 날은 남음).
  - 예전 저장 형식은 열 때 자동으로 옮긴다(사이클은 날 순서 그대로, 요일 방식은 날의 요일 칸으로).
- **만들기 화면**(`RoutineDetailScreen`): 1 방식·이름 → 2 반복 일수·오늘 몇 일차(N일 반복만) → 3 날 만들기 → 4 칸 배치(칸마다 체크, 눌러서 날 고르기, ▲▼ 옮기기, 빈 칸에 차례로 채우기) → 5 확인. ‘이전/다음’으로 한 단계씩 넘어가고, 이미 만든 루틴은 확인 단계에서 고치고 싶은 단계로 바로 이동한다.
- 새 날은 처음 비어 있는 칸(또는 시트에서 고른 칸)에 자동으로 놓인다. 날을 지우면 그 날이 놓인 모든 칸이 비워진다. 휴식은 날이 아니라 빈 칸이다.
- 가져오기: 사이클은 가져온 순서대로 칸이 되고(반복 일수 = 날 수), 요일 방식은 각 날의 요일 칸에 놓인다(휴식은 빈 칸).
- 테스트: `tests/run.ts`(칸 검증·이전 형식 이전·배치·반복 일수·방식 변환), `tests/db.ts`(저장·일정 조회·삭제·가져오기). 화면(5단계 UI)은 실제 기기에서 확인하지 못했다.

## 마무리 보강: 홈 Day 표시 · 아래 여백 · 대체 운동 · 연습 세트 · 움직임 경로
- **홈 오늘 카드**: 오른쪽 위를 ‘Day 3 ›’ 한 줄로 단순화(요일 고정 루틴이면 요일, 오늘만 바꿨으면 바꾼 날 이름). 누르면 날 고르기.
- **아래 여백**: 시트·팝업(오늘 날 고르기, 시작 전 미리보기, 칸 고르기, 세트 입력, 종목 선택, 1RM 계산기, 완료 요약)은 폰이 알려 주는 아래쪽 안전 영역(`useSafeAreaInsets`)만큼 자동으로 띄운다. 폰 크기·내비게이션 방식(3버튼/제스처)에 상관없이 버튼이 가려지지 않게 한 것이며, 고정값을 쓰지 않는다. 시작 전 미리보기는 위쪽 설정·목록이 함께 스크롤되고 ‘닫기/운동 시작하기’ 버튼은 항상 보인다.
- **빈 루틴 정리**: ‘+ 새 루틴’은 바로 만들어 1단계로 들어가므로, 이름을 정하지 않고 날도 만들지 않은 채 나가면(‘새 루틴’, 날 없음) 루틴 탭에서 자동으로 지운다.
- **슈퍼세트 순서**: 시작 전 순서 변경에서 슈퍼세트로 묶인 종목은 한 덩어리로 움직인다.
- **나중에 하기·건너뜀 유지**: 운동(세션)별로 저장해서 화면을 나갔다 와도 이어진다.
- **홈 성장 카드**: 성장 분석에서 고른 운동(여러 개)마다 최근 최고 중량 막대 그래프(그래프 색) 표시.
- **대체 운동 ⇄**: 운동 중 종목 옵션에서 완료한 세트가 없을 때만 다른 종목으로 교체(세트 수·순서·슈퍼세트·메모 유지, 입력만 해 둔 값은 비움).
- **연습 세트 추천**: 본 세트 무게(없으면 지난 기록)의 40%×8 → 60%×5 → 80%×3을 증량 단위에 맞춰 준비 세트로 추가. 통계에는 들어가지 않는다.
- **움직임 경로**: 카메라 세기 화면에서 손목(바벨과 비슷)·팔꿈치·엉덩이·무릎이 지나간 길을 선으로 그리고 위아래 움직임 폭을 보여 준다. 몸이 가려지면 그 순간은 건너뛴다. 실제 바벨 위치를 직접 인식하는 것은 아니다.
- 테스트: 슈퍼세트 이동, 연습 세트 계산, 경로 계산(`tests/run.ts`), 빈 루틴 정리·대체 운동·연습 세트 저장(`tests/db.ts`). **화면(여백, 홈 표시, 그래프, 경로 선)은 실제 기기에서 확인하지 못했다.**

## 순서 바꾸기는 항상 손잡이(≡)로 · 데이터베이스 열기 재시도
- 시작 전 미리보기의 종목 순서, 루틴 만들기 4단계(칸 배치)의 칸 순서는 ▲▼ 버튼 대신 오른쪽 ≡ 손잡이를 길게 누른 채 끌어서 바꾼다(날 편집·날 목록과 같은 방식). 미리보기에서는 슈퍼세트로 묶인 종목이 한 덩어리로 움직이고, 순서는 이번 운동에만 적용된다. 앞으로 순서를 바꾸는 화면은 모두 이 방식을 쓴다.
- 데이터베이스 열기가 일시적으로 실패하면(예: `NativeDatabase.execAsync` NullPointerException) 최대 3번까지 쉬었다가 다시 열고, `journal_mode` 설정이 실패해도 그 설정만 건너뛴다. 그래도 실패하면 오류 화면에 ‘다시 시도’ 버튼이 나온다. 이 재시도가 실제 폰에서 문제를 풀어 주는지는 확인하지 못했다.

## 영상 점 추적(궤적) · 운동 표 · 동작 유형 판별
- **영상 궤적**(프로필 → ‘영상 궤적 (점 추적)’): 영상을 골라 멈춘 화면에서 따라갈 곳을 누르면(점 1개, 또는 점 2개로 선) 그 점의 움직임만 선으로 그린다. 사람 전체를 분석하지 않고 **찍은 곳 주변의 작은 조각만 프레임마다 찾으므로** 자세 분석보다 훨씬 가볍다. 영상은 폰 안에서만 처리된다(서버 없음).
  - 구간(시작 장면~‘여기까지’)의 프레임을 초당 약 15장, 긴 변 320px 흑백으로 읽어 ZNCC(밝기가 변해도 모양이 같으면 높은 점수)로 근처에서 가장 닮은 곳을 찾는다. 닮은 정도가 기준(0.6) 아래로 떨어지면 ‘놓쳤다’고 알리고 멈춘다(잘못 이어붙이지 않음). 그 장면에서 점을 다시 누르면 거기서부터 이어서 따라가 앞부분과 합친다.
  - 결과: 위아래·좌우 움직임 폭(영상 높이 대비 %), 왕복 횟수(대략), 점 2개일 때 선의 기울기(수직 기준). 영상 크기·회전·검은 여백을 보정해 누른 곳을 영상 좌표로 바꾼다.
  - 기준 구현은 `src/domain/pointTrack.ts`(테스트 대상), 안드로이드 구현은 `modules/video-tracker`(Kotlin, `MediaMetadataRetriever`), 계산 보조는 `src/domain/trackMath.ts`. ‘영상을 전부 훑는다’는 점은 같지만 프레임마다 하는 일이 작아서 빠르다. **프레임을 읽는 시간은 줄일 수 없어** 긴 구간은 몇 초~수십 초 걸릴 수 있다.
  - 한계: 가려지거나 빠르게 흔들리거나 모양이 크게 바뀌면 놓치거나 조금씩 어긋날 수 있다(그럴 때 다시 눌러 고친다). 카메라가 움직이면 궤적에 카메라 움직임이 섞인다. **실제 폰에서는 아직 확인하지 못했다**(합성 프레임 테스트만 통과).
- **운동 표**(`src/domain/exerciseTable.ts`): 대중적인 운동 182개(부위·장비·움직임 유형·자세·등급). 순위는 공개 통계(StrengthLog, Fitbod, Arvo 등)를 참고한 대략의 순서이며 정확한 100위 순위가 공개된 곳은 없다.
- **동작 유형 판별**(`src/domain/patternClassify.ts`): 카메라 세기 화면에 ‘지금 동작은 ○○ 같아요 (확신도)’와 다른 후보를 보여 준다. 운동 이름이 아니라 **움직임 유형(15종)**만 구분한다 — 바벨/덤벨/머신 같은 도구는 관절만으로 알 수 없다. 규칙·점수 방식이고 학습 모델이 아니다.
  - 최근 6초의 관절 프레임을 1초마다 판별한다. 떨림은 앞뒤 5프레임 평균으로 줄이고, 몸통 길이로 크기를 맞춘다. 어깨 폭÷몸통 길이로 카메라 방향(정면/옆면/비스듬)을 추정해, 정면에서 무릎·고관절 각도가 안 보이는 스쿼트·힙힌지는 안내 문구를 붙인다.
  - 루틴의 현재 운동이 표에 있으면 ‘✓ 비슷한 동작 / △ 후보에만 있음 / ✕ 다른 동작처럼 보임’을 함께 표시한다.
  - 머리 위로 밀기와 수직 당기기는 관절 움직임이 거울상이라 카메라로 확실히 가를 수 없어 둘 다 후보로 보여 준다.
  - **검증은 합성 자세(2D 뼈대 12종, ±2% 떨림 포함)로만 했다.** 실제 사람 영상·실제 포즈 추정 잡음으로는 아직 확인하지 못했으므로 기준값(임계값)은 실사용 후 조정이 필요하다.
- 테스트: `tests/run.ts`에 점 추적(합성 프레임: 이동·조명 변화·사라짐), 궤적 계산, 좌표 변환, 이어붙이기, 운동 표·이름 찾기, 동작 판별(+떨림), 루틴 비교 추가(총 107개). `tests/poseSynth.ts`는 합성 자세 생성기.

## 카운트 오탐 방지 · 영상 도구를 숫자 전용 점/직선/호로
- **카운트 오탐 수정**(몸이 일부만 보일 때 혼자 올라가던 문제): 화면 밖으로 나간 관절은 모델이 위치를 추정해 높은 신뢰도로 내놓지만 위치가 떨리므로, 신호마다 필요한 관절이 **화면 안(가장자리 3% 안쪽)에서 신뢰도도 충분할 때만** 쓴다. 값이 **연속 4프레임** 들어와야 인정(가장자리를 들락날락하는 값 무시), 관절마다 왼쪽/오른쪽을 한 번 고르면 **계속 그쪽만** 사용(쪽이 바뀌는 순간 각도가 튀던 문제), 한 프레임짜리 튀는 값은 한 번 건너뜀, 으쓱·뒤꿈치 문턱 상향, 골반이 화면 밖이면 위치 신호 문턱 ×1.5. 상체만 보여도 컬·레이즈는 그대로 센다.
- **카메라 화면 뼈대 숨김**: 측정은 내부에서만 하고 화면에는 ‘● 인식 중(상체만)’ 표시만 남긴다(‘움직인 길 보기’는 선택했을 때만 그림).
- **좌표 기록 저장**(`poseLog.ts`): 카메라 화면의 ‘최근 60초 좌표 기록 저장’으로 영상 없이 관절 좌표(소수 3자리)와 카운트가 올라간 순간을 JSON으로 공유한다. 오탐이 또 나면 이 파일로 원인을 확인해 기준값을 맞춘다. **문턱 값은 아직 실제 데이터로 맞추지 못했다.**
- **영상 도구(수치 전용)**: 점 1개(궤적: 위아래·좌우 움직임, 총 이동 거리, 왕복), 직선(점 2개: 기울기·길이), 호(점 3개 = 한쪽 끝·가운데·반대쪽 끝: 휘어짐 = 가운데 점이 양 끝 연결선에서 벗어난 거리 ÷ 선 길이, 호 중심각)를 ‘지금 값’과 구간 최소~최대로 보여 준다. 코칭 문구·그래프·판정은 없다. 점을 놓치면 그 장면에서 다시 눌러 이어 추적하는 방식은 그대로.
- **점이 안 찍히던 문제**: 영상은 `textureView`로 그리고 투명한 터치 전용 판을 위에 얹었으며, 누를 때마다 화면에 결과(찍은 위치·이유)를 문구로 남긴다. 원인을 폰에서 확인하지 못했으므로 이 수정이 문제를 풀었는지는 알 수 없다.
- 테스트(`tests/run.ts`, 총 113개): 화면 안 확인, 일부만 보일 때 0회·상체 컬 5회, 좌우 번갈아 바뀌는 신뢰도, 튐 제거, 좌표 기록, 선·호 수치.

## 카메라 전환 · 화면 정리
- **카메라**: 기본은 전면. 앞/뒤 전환은 글자 버튼 대신 미리보기 오른쪽 위의 ‘카메라+회전 화살표’ 아이콘(44px)으로 한다. 전환하면 카메라 화면을 통째로 새로 만들어 다시 켜서(제자리 전환 시 검은 화면이 남던 문제 대응) 앞/뒤 좌표가 섞이지 않게 모아 둔 좌표·움직인 길 선도 비운다(횟수는 유지). **검은 화면이 실제로 해결됐는지는 기기에서 확인하지 못했다.**
- **카메라 화면 정리**: 위에서부터 미리보기 → 지금 동작 → 세트 진행 → 횟수 → ‘이 횟수 사용’ → ‘처음부터 / 설정’. 방식·세트·소리·운동 종류·움직인 길·세는 기준·정밀도·좌표 기록 저장은 접이식 ‘설정’ 카드로 묶었다(기본 접힘).
- **공통 UI**: 작은 버튼 38px·칩 34px 이상으로 터치 영역 확대, 뒤로가기 40px 터치 영역, 상단 헤더 높이 통일, 하단 탭 간격 조정. 색·글꼴 체계는 그대로(흑백, 색은 그래프에만). 실제 폰 화면에서는 확인하지 못했다.

## 점 추적 안정화 + 세는 범위 강/중/약
- 원본 헬스장 영상(55초)으로 PC에서 먼저 시험: 이전 방식은 손목 띠 점이 8초쯤 팔뚝으로 미끄러지고 12.6초에 놓침 → 새 방식은 12초대까지 띠 위에 유지(머리 점은 30초 내내 유지). 12.4초 이후는 손목이 돌아 놓치는 것이 맞는 상황.
- 조각 반경 12 / 탐색 범위 26 / 놓침 문턱 0.5, 템플릿은 점수 0.8 이상일 때만 새 모습을 50% 섞음(통째 교체 → 미끄러짐 방지).
- 탐색은 조각을 2칸씩 건너뛰며 넓게 → 최고점 주변 촘촘히 → 점수 분포로 소수점 위치 보정(속도·떨림 개선).
- 가장자리 3px 안으로 들어가면 화면 밖으로 보고 놓침 처리, 시작점 무늬가 약하면(밝기 표준편차 12 미만) 안내 문구.
- 통계: 0.4% 안쪽 움직임은 떨림으로 보고 0 처리.
- 앞뒤 양방향 검증은 넣지 않음(끝점이 틀리면 앞 구간까지 의심되는 문제를 풀지 못함).
- 갯수 세기: 세는 범위를 강(20°~)·중(35°~)·약(50°~)으로 표기. 안 세지면 강, 헛세면 약.
- 폰 실측 전: 추적 속도와 정확도, Kotlin 포팅은 CI 컴파일로만 확인.
